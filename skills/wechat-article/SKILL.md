# 公众号长文

写一篇读得完、愿意转、能转化的公众号文章。默认 2000–3000 字。

## 工作流程

```
- [ ] 1. 补齐输入（最多问 2 个问题）
- [ ] 2. 选文章类型 → 写一句话核心观点
- [ ] 3. 交大纲（用户说「直接写」则跳过确认）
- [ ] 4. 5 个标题 + 摘要 + 封面建议
- [ ] 5. 写开头（前 150 字）
- [ ] 6. 写正文
- [ ] 7. 写结尾与唯一转化动作
- [ ] 8. 自检（脚本 + 清单），修到通过
- [ ] 9. 按模板交付
```

### 1. 补齐输入

缺了会写错才问，最多 2 个，优先：**读者是谁**（同行/客户/大众，决定术语深浅）、**读完要做什么**（关注/咨询/报名/购买）。素材里没有的案例、数据不要编，用【待补充：…】标出。

### 2. 文章类型（选 1 个骨架）

| 类型 | 骨架 |
|---|---|
| 观点文 | 现象 → 常见看法 → 我的判断 → 3 个论据 → 对读者的建议 |
| 干货教程 | 问题场景 → 为什么难 → 步骤 1/2/3 → 常见错误 → 工具/清单 |
| 案例复盘 | 背景与目标 → 做了什么 → 结果数据 → 关键决策 → 可复用经验 |
| 品牌故事 | 一个具体时刻 → 起因 → 困难 → 转折 → 今天 → 价值观 |
| 活动/新品 | 读者收益 → 是什么 → 3 个亮点 → 时间地点价格 → 如何参与 |

用户给的是数据/复盘材料默认「案例复盘」；给的是观点默认「观点文」。

### 3. 大纲

```
标题（暂定）：
核心观点（一句话）：
读者看完能获得：
开头钩子：
01 小标题 —— 要点 / 素材
02 小标题 —— 要点 / 素材
03 小标题 —— 要点 / 素材
结尾 + 转化动作：
```

先交大纲请用户确认。用户已说「直接写全文」或素材完整时，大纲随成稿一起交付，不停下来等。

### 4. 标题、摘要、封面

- **标题 5 个**：建议 15–28 字（后台上限 64 字），单看标题就知道讲什么；推荐 1 个并说明理由。标题公式见 [references/titles-and-openings.md](references/titles-and-openings.md)。
- **摘要 1 条**：≤120 字（后台上限），补充标题没说的信息；建议 ≤54 字以保证在卡片上完整显示。
- **封面建议**：画面主体 + 是否加字。

### 5. 开头（前 150 字）

前 3 段内必须让读者知道：这篇讲什么、和我有什么关系、为什么听你说。默认用「场景代入」或「结论先行」；其他 4 种开头写法见 [references/titles-and-openings.md](references/titles-and-openings.md)。

### 6. 正文

- 小标题 3–6 个，每个是一个完整观点（「先算清房租占比」优于「关于房租」），用 01 / 02 / 03 编号。
- 每 300–500 字一个小标题；每段 2–4 行（手机一屏）。
- 每个观点配「例子 / 数据 / 金句」之一；金句单独成段加粗，便于截图转发。
- 引用数据注明来源与时间。少用「首先、其次、综上所述」等公文腔。
- 用 Markdown 输出，在需要配图处写 `【配图：画面描述】`。排版参数（字号、行距、配色）见 [references/layout.md](references/layout.md)，用户要求排版建议时读。

### 7. 结尾与转化

一段总结 + **一个**明确动作（最多两个）。示例：
- 互动：「你店里最难的是哪件事？留言区聊聊，我挑 3 个写下一篇。」
- 转化：「需要诊断的老板，后台回复『诊断』，前 20 位免费。」（写清名额与截止时间）

### 8. 自检（必须执行）

```bash
python3 scripts/check_copy.py --platform wechat --title "<推荐标题>" --digest "<摘要>" --body-file <正文文件>
```

检查标题 ≤64、摘要 ≤120、诱导分享话术、绝对化/医疗用语。ERROR 必须改；无 Python 时按「交付前清单」人工核对。

### 9. 交付模板

```markdown
## 标题备选
1. …（推荐：<理由>）
2. … 3. … 4. … 5. …

## 摘要
…

## 封面建议
…

## 大纲
…

## 正文
<Markdown 全文，含【配图：…】>

## 文末引导
…

## 发布建议
- 首条留言：…
- 朋友圈转发语：…
- 需用户补充：<【待补充】项；没有则写「无」>
```

## Gotchas / 常见坑

- **标题上限 64 字、摘要上限 120 字**（腾讯客服官方说明）；不填摘要时，卡片默认抓取正文前 54 字——所以要么认真写摘要，要么让正文第一句就能当摘要。
- **诱导分享 / 诱导关注会被处罚**：微信官方规则禁止「分享后才能继续看」「转发集赞领奖」「关注后才能看答案」，以及「不转不是中国人」「转发后一生平安」等煽动话术；处罚包括禁止转发、删文、封禁能力甚至封号。抽奖/福利只能写「留言参与」等不以分享为条件的方式，并写清规则、时间、主体。
- **发表后几乎不能改**：已发表文章每篇只有 1 次修改机会，且只能改少量字（2025 年 4 月调整后正文可改 120 字以内，标题可改 3 字；以后台为准）。所以数字、日期、价格、人名在交付前必须核对，不确定的一律【待补充】。
- **公众号正文对外部 AI 爬虫不可见**：`mp.weixin.qq.com` 的 robots.txt 不放行文章页。如果用户希望文章也被 DeepSeek、Kimi 等引用，建议同步一份到可公开抓取的官网（详见 geo-cn 技能）。
- **广告法同样适用于推文**：绝对化用语、非医疗产品的疗效宣称、无来源数据都不能写；带购买链接的测评/体验文须标明「广告」。凡涉及推销、价格、功效、数据引用，先读 [references/ad-compliance-cn.md](references/ad-compliance-cn.md)。
- **医疗、金融、教育类**不做收益或效果承诺（「稳赚」「保过」「包治」）。
- **转载与引用**：转载需授权并注明出处；引用他人观点注明作者。

## 交付前清单

- [ ] 5 个标题均 ≤64 字（建议 15–28 字），与正文一致
- [ ] 摘要 ≤120 字，补充了标题没说的信息
- [ ] 开头 150 字内交代主题与读者收益
- [ ] 小标题可独立成句、编号统一
- [ ] 每个观点有支撑，数据有来源与时间，缺失处【待补充】
- [ ] 结尾只有 1–2 个动作，无诱导分享/关注
- [ ] 无绝对化用语、无疗效或收益承诺
